01

What it checks in AI-written code

Coding assistants write fast and check nothing. These are the mistakes they make most, and Meridian finds each one by reading the code's structure, not by asking another model. Every finding links to the line it's about.

BROKEN

Imports that point nowhere

The AI imported a project file that doesn't exist, or got the path wrong. Meridian lists every relative import that resolves to no loaded file, with the line. (Package imports are treated as external.)

DUPES

Code it wrote twice

Assistants often rebuild a helper that already exists somewhere else. Meridian finds functions and classes with the same name in different files.

CYCLES

Circular dependencies

File A imports B, which imports A. These cause hard-to-trace bugs. Meridian walks the whole import graph and lists every loop.

UNTESTED

Files nothing tests

Which code files have no matching test: no test file shares their name and no test imports them. Untested files that much of the project depends on also surface in the signals digest.

IMPACT

What a change touches

Name a file the AI edited and see every file that depends on it, directly or through other files. That's your review list.

SIGNALS · DRIFT

The short list, and what moved

A ranked digest of the three to five findings most worth your attention, plus which files appeared, disappeared or changed shape since your last session.

ALSO · never-imported files (orphans) · most-depended-on files (hubs) · environment variables read (env) · TODO/FIXME tags (todos) · definitions and references · 10 languages

WHAT IT DOESN'T CHECK (YET) · it doesn't run your code or your tests · it doesn't scan for security vulnerabilities · it doesn't prove logic is correct. It checks structure: what exists, what connects to what, and what's missing. Use it alongside your tests and code review, not instead of them.

02

How it checks code without AI

The checks are ordinary program logic, the same kind of analysis a linter or an IDE's "find references" does. Nothing in them guesses. Here's what happens when you load a project.

STEP 01 · READ

Your browser reads the files

You drop a folder on the page. The browser reads the files into the tab's memory. They aren't uploaded anywhere; there's no server to upload them to. Binary files, huge files and folders like node_modules are skipped and listed.

STEP 02 · MAP

It builds a map of the project

Language-specific rules scan each file for definitions (functions, classes, types), imports, exports, tests and entry points across 10 languages. Then it resolves each import to the file it points at. The result is a graph: every file, and every connection between files.

STEP 03 · CHECK

The checks are questions about that map

"Which imports didn't resolve?" "Is there a loop in the graph?" "Which names are defined twice?" "Which files does nothing test?" These are exact lookups and graph walks, so the same project always gives the same answer, and each answer points at the lines it came from.

STEP 04 · OPTIONAL

Ask a model only when you need reasoning

For "why" and "how should I" questions, plug in your own Anthropic, OpenAI or local model key. Meridian attaches its verified findings so the model starts from facts, and PREVIEW SEND shows the exact payload first. Answers that need a model are labelled REQUIRES MODEL REASONING; answers that don't are labelled KNOWN LOCALLY.

WHY NOT JUST ASK AN AI?

Checking AI with AI moves the problem

  • It's repeatable. Run the same check twice and get the same result. A model can answer differently each time.
  • It can't make things up. A finding exists only if the line exists. Click it and you're there.
  • It knows its limits. If a question needs judgement, it says so instead of guessing.
  • It's free and offline. No key, no per-question cost, no network.
THE HONEST LIMITS

Pattern rules, not a compiler

  • The map comes from fast pattern rules, not a full compiler, so unusual code can be missed. Depth varies by language; JavaScript and TypeScript are strongest.
  • It sees imports written in the code. Files wired up at runtime (plugins, dependency injection, script tags) can look unused when they aren't, and the answers say so.
  • Tuned for projects up to about 8,000 files.

04

Who it's for, and why there's no backend

WHO IT'S FOR

Teams shipping code that AI helped write

  • Developers and reviewers checking what an assistant changed before it merges.
  • Engineering leads getting people productive in large or unfamiliar codebases.
  • Security and platform reviewers who have to sign off on anything that touches source.
  • Teams with data-residency or vendor-risk rules that rule out hosted code assistants.
WHY NO BACKEND

No server, so we hold no copy of your code

  • No vendor server holds your code, so there is no copy of ours to breach, subpoena or retain.
  • Requests go from the browser straight to your provider, under your agreement, account settings and data terms.
  • Meridian adds no party that sees code, so data-residency and vendor-risk reviews have fewer parties to clear.
  • Saved projects and workspaces keep metadata only. Close the tab and the files are gone.

05

For security and vendor-risk reviews

The questions reviewers ask, with direct answers. You can check each point in the source and in your browser's network inspector.

WHERE CODE LIVES
In the memory of the browser tab that loaded it, and nowhere else. Close the tab and it is gone. Saved projects and workspaces keep metadata only (names, file counts, selection, settings) in that browser's IndexedDB.
WHAT LEAVES, AND WHEN
Only when you ask a model a question: the question, the files you ticked, short line-numbered excerpts the local index found (with GROUND on, the default; these can come from any loaded file, ticked or not), any evidence you pinned, and earlier turns of the conversation go directly from the browser to the provider you configured. SMART mode also sends a project map of the ticked files. PREVIEW SEND shows the exact payload first. In LOCAL mode, nothing is sent.
OUR SERVERS
None. Meridian is static files on GitHub Pages: no accounts, no database, no telemetry sent to us. Nothing runs on our side. The product is the static source, which you can review or self-host at a pinned commit. GitHub may log standard request data (such as IP addresses) when the page loads.
MODEL PROVIDER
Anthropic, OpenAI, or any OpenAI-compatible endpoint, under your own key, agreement, region and data terms. Local models (LM Studio, Ollama) work on the hosted page with CORS enabled for this site (see the user guide). For an internal gateway or a regional endpoint, host your own copy and add its address to the page's security policy.
API KEYS
Stored in that browser's localStorage, one per provider, and sent only to that provider. Never put into share links, bundles, exports or the usage log.
SHARE LINKS
The link carries the selected files in the part after #, which browsers never send in a request, so no server receives it. It is the code itself: anyone who has it can read it, and it can't be revoked. Secret-looking files (.env, private keys) start unticked.
USAGE ANALYTICS
Off by default, and nothing is recorded while off. When on, events stay in the browser and hold no code, paths or keys; question text needs a separate switch. Optional sending goes only to an endpoint you enter (localhost on the hosted page). LOCAL-mode events are never sent.
PAGE HARDENING
No third-party scripts. A content security policy allows scripts from this site only, and lets them connect only to the two provider APIs and localhost. The workbench refuses to run inside a frame.
NOT OFFERED
No certifications, SSO, admin console, central policy controls, audit-log service or SLA. Meridian is a free beta run by one person. The no-backend design is the control.

Need it in writing? Send your reviewer the one-pager (it prints to one page), the privacy policy and the source.
